# 対象範囲と設計の原則

- 決定日: 2026-11-14
- 状態: 採用

この文書は、本ツールが「何を作り、何を作らないか」と、機能を足すときに守る
安全面の原則を残すためのもの。方針を変えるときはこの文書を更新し、末尾の
「変更履歴」に理由を追記すること。

## 背景

当初の要件（[requirements.md](../requirements.md)）は「Windows で macOS 風の
ライブ変換を実現する変換エンジン」だった。実装が進むにつれ、変換の質を上げる
ために作った仕組み（全キー入力を受け取る常駐フック、UI Automation による
入力欄の把握）がそのまま変換以外の操作にも使えることが分かり、次のような
機能が加わった。

| 時期 | 機能 | 変換との関係 |
|---|---|---|
| 2026-08 | コマンドモード（ターミナル） | 変換ではない。打鍵の学習を流用 |
| 2026-09 | 確定後の復元（変換キー） | 確定した後の操作 |
| 2026-09 | パスワード欄・管理者権限アプリでの自動停止 | 安全のための判定 |
| 2026-10 | 誤変換の記録（Ctrl+Alt+R）、入力欄の文章を文脈に使う | 変換の前後 |
| 2026-11 | 入力欄ワープ（Ctrl+無変換） | 変換ではない。入力欄の把握を流用 |

結果として本ツールは「変換エンジン」から「ライブ変換を核にした日本語入力の
効率化ツール」になった。この文書はその実態に合わせて範囲を言語化する。

## 位置づけ

**ライブ変換を核にした、Windows 向けの日本語入力効率化ツール。**
文字を入力する作業（どこに打つか → 打つ → 変換する → 確定する → 直す）の
手間を減らす。機能は次の3層に分ける。

| 層 | 内容 | 主な置き場所 |
|---|---|---|
| 1. 変換 | ライブ変換、判断層、学習、英単語の自動判定、もしかして | `crates/common` |
| 2. 確定の前後 | 確定後の復元、句読点の確定、誤変換の記録、候補一覧 | `crates/common/src/conversion.rs`、`hook-dll` |
| 3. 入力欄まわり | 入力欄ワープ、環境ごとのモード、コマンドモード | `crates/hook-dll` |

層1は OS に依存しないよう保ち、CLI とゴールデンテストで検証できる状態を守る。
層2・層3は Windows のフックと UI Automation に依存する。

## 作るもの・作らないもの

新しい機能は次の3つをすべて満たすときだけ入れる。

1. **文字を入力する作業の手間を減らす**ものであること。入力欄に文字を入れる前後
   （欄に移る・打つ・変換する・確定する・直す）の操作に限る。
2. **キーボードから手を離さずに済む**方向の機能であること。
3. **ローカルで完結する**こと。入力した文章や打鍵を外部へ送らない。

作らないもの（上の条件から外れる、または別のツールの仕事）:

- 入力と関係のない汎用ランチャー・ウィンドウ管理・マクロ実行（入力欄ワープは
  「打つ場所へ移る」ことに限り、ウィンドウの配置や任意のボタン操作はしない）
- 確定済みの文書の書き換え、文章全体の校正・要約・言い換え（もしかしては
  入力中の未確定テキストの限定した誤記だけを扱う）
- 入力した文章をサーバーや外部の AI に送る機能
- クリップボード履歴など、入力欄の外のデータを集めて保存する機能

迷ったときは「Ctrl+Space（緊急 OFF）で止めたときに、ユーザーがそれも止まって
ほしいと思うか」で判断する。止まってほしくないものは本ツールの範囲外。

## 名前

名前は **IME Live Converter** のまま変えない（2026-11-14 判断）。

- 「IME」は Input Method Editor、つまり入力全般を担うものを指すので、変換以外の
  入力操作を含む今の範囲にも合っている。「Live Converter」は他の IME との
  違い（ライブ変換）を表しており、核は今もそこにある。
- 改名の費用が大きい。リポジトリ名・配布 ZIP 名・インストール先
  （`%LOCALAPPDATA%\Programs\IMELiveConverter`）・学習データの場所
  （`%LOCALAPPDATA%\IMELiveConverter`）・自動起動タスク名・スタートメニューの
  名前が揃って変わり、データの場所を変えると学習内容の引き継ぎ処理が要る
  （[release-and-versioning.md](release-and-versioning.md) の基準では MAJOR 変更）。
- 位置づけの変化は、名前ではなく説明文（README 冒頭・配布物の README）で伝える。

改名するなら、学習データの場所を固定する前、つまり v1.0.0 のタグを打つ前が
最後の安い機会になる。1.0.0 以降に変える場合は、旧フォルダからの移行処理と
MAJOR の版上げを伴う。

## 安全面の原則

層3の機能は「アプリの外側から別のアプリを操作する」ので、変換とは別の種類の
不具合（フォーカスを奪う、他のアプリの操作を化けさせる、キーが消える）を
起こしうる。次を守る。

1. **フックはすぐ返す**。キーボードフックは 300ms 以内に返さないと Windows が
   生のキーを通してしまい、遅れが続くとフック自体を外す。UI Automation の走査や
   ファイル書き込みなど時間のかかる処理は専用スレッドに渡し、フックは要求を
   積むだけにする（入力欄ワープはこの形）。
2. **判定が付くまでは「安全」と見なさない**。パスワード欄・管理者権限アプリの
   判定は「未判定／安全／危険」の3値で持ち、「安全」のときだけ処理する。
   新しく「この場所では動かない」判定を足すときもこの形にする。
3. **押されたままの修飾キーに注意する**。ホットキーを押した瞬間は Ctrl 等が
   物理的に押されたままなので、合成したキーやクリックはそれと組み合わさって
   化ける（Backspace が Ctrl+Backspace に、クリックが Ctrl+クリックに）。
   クリックの合成は使わず、フォーカスは UI Automation の `SetFocus` で移す。
4. **自分で送ったキーには印を付ける**。`SendInput` で送るキーには自己送信の印を
   付け、フックが自分の送ったキーを処理し直さないようにする。
5. **前面ウィンドウを勝手に変えるのは、ユーザーがキーで頼んだときだけ**にする。
   自動で別のウィンドウを前面に出す機能は作らない。
6. **止める手段を必ず用意する**。全機能は `Ctrl+Space` で止まる。新しい機能は
   この緊急 OFF の対象に含める。
7. **実機での打鍵はユーザー本人が行う**。キー入力を自動で送る検証は、送り先の
   ウィンドウを取り違えると別のアプリへ打鍵が漏れるので、前面ウィンドウを照合
   してから送り、照合できなければ送らない。

## 未対応の課題

- 層3の機能だけを個別に無効にする設定が無い（今は Ctrl+Space で全体を止める
  ことしかできない）。機能が増えたら、機能ごとの ON/OFF を設定ウィンドウに
  まとめる。
- ホットキー（変換キー・Ctrl+無変換など）の割り当てを変える設定が無い。
